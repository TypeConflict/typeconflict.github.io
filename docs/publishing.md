# 發布指南

## 推薦入口：GitHub 登入後台

開啟 <https://corner-publish-studio.irene-qh-yan.workers.dev/>，以 `TypeConflict` 登入。手機和電腦使用同一個網址與發布資料。

1. 選 Note、Blog 或 Photo。
2. 填寫內容；Tags 使用逗號分隔。Blog 另填標題與摘要。
3. Photo 選一張圖片，發布時會在裝置上縮小到長邊最多 1800px，轉成 WebP；原始檔上限 25MiB，轉檔後上限 5MB。
4. 點發布，等待成功訊息，再查看公開網站。GitHub 提交成功和 Pages 完成部署是不同階段。

後台已發表列表可編輯或刪除內容。編輯會保留原本日期，因此修改舊照片不會自動成為最新照片。新的照片貼文每篇一張；舊多張照片貼文仍可顯示及刪除。以手機後台重新儲存舊多張照片貼文時，目前只保留表單載入的第一張圖片引用；要保留全部舊圖片，請勿使用此表單重新儲存該筆，改用直接編輯 JSON。

手機後台沒有草稿自動儲存。離開、重新整理、切換類別或清空前，請自行保留未發布文字。已發布資料在各裝置共用。

## Blog 的簡易 Markdown

公開網站目前支援：

```text
## 大標題
### 小標題
一般段落
**粗體**、*斜體*、`行內程式碼`
- 清單項目
> 引文
[連結文字](https://example.com)
```

這不是完整 Markdown 引擎；表格、程式碼圍欄、Markdown 圖片語法尚未支援。

## 兩個保留的替代入口

| 入口 | 特性 | 適用情況 |
| --- | --- | --- |
| `/admin.html` | 輸入短效、限定單一 repo 的 fine-grained PAT；token 僅留頁面記憶體 | GitHub App 後台暫時無法使用時 |
| `/#studio` | 只在當前瀏覽器儲存與匯出 JSON，無法直接發布 | 本機試寫、備份或離線準備 |

PAT 備用介面需 Contents 讀寫權限，只授權這個 repo。重新整理或關閉頁面後須再次提供 PAT；不要改成永久存放於瀏覽器或公開程式。

本機編輯器會把選擇的照片嵌入 JSON。不要用大量內嵌圖片建立長期相簿，也不要用舊的完整 JSON 覆蓋其他裝置較新的資料。

## 跨裝置與錯誤處理

- 一台裝置發布後，另一台開始編輯前先按「更新」。
- 若顯示內容已在其他裝置更新（409），先複製未發布文字，再更新並重新編輯。
- 已登入但內容載入失敗：依畫面錯誤檢查網路及 GitHub App 權限，再按更新。初始載入失敗時發布鈕會停用。
- 若登入後仍停在原頁：重新開啟後台首頁，確認載入目前版本。維護者應查看瀏覽器程式錯誤；不要重複使用含授權碼的 callback 網址。
- 發布成功但前台未變：確認 Pages 部署完成。若曾使用 `/#studio`，本機草稿可能覆蓋前台顯示；先匯出本機草稿，再重設本機編輯，或用另一個瀏覽器查看。
- 刪除貼文不會刪掉 `assets/photos/` 的檔案或 Git 歷史。
- 上傳照片與寫入貼文是兩次提交；後者失敗可能留下未使用的圖片。刪除前應確認沒有任何內容引用。

## 驗收建議

以願意公開的內容依序測試 Note、Blog、單張 Photo，檢查公開網站、Photos 列表及首頁 Latest snapshot。再確認關閉重開、登出、手機加入主畫面後的登入。登出會移除該次 session；不是撤銷整個 GitHub App。
